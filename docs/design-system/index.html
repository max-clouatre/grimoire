Viewers

Name a data file with a viewer extension and Grimoire renders it. No HTML needed, and both are two-way.

*.kanban.json → board

{
  "title": "Board", "idPrefix": "app",
  "columns": [{ "id": "todo", "name": "To do" }, { "id": "doing", "name": "Doing" }, { "id": "done", "name": "Done" }],
  "cards": [{ "id": "app-001", "title": "…", "column": "doing", "milestone": "M1",
              "tags": ["ui", "blocked"], "owner": "claude", "notes": "…" }]
}

*.dashboard.json → project status

{
  "title": "Project", "subtitle": "…",
  "board": "20-board.link", "roadmap": "30-roadmap.link", "decisions": "50-decisions.link",
  "health": { "status": "on-track | at-risk | off-track", "note": "…" },
  "milestones": [{ "id": "M1", "name": "…", "goal": "…" }]
}

Milestone progress, blocked work and counts are computed live from the board's cards (tag blocked marks a blocker).

Two-way API

Every artifact gets window.grim. Writes are limited to data files inside the artifact.

const todos = await grim.readJSON("todos.json");      // a file in this artifact
await grim.writeJSON("todos.json", todos);             // .json .md .txt .csv .yml
const board = await grim.peer("20-board.link").readJSON(); // another artifact on this channel
grim.focus("30-roadmap.link");                          // bring a tab into view
grim.onChange(({ artifact, self, by }) => reload());  // handle changes yourself (no page reload)

Making a theme

  1. Copy .grimoire/themes/default.css to .grimoire/themes/my-theme.css.
  2. Edit @name, @description, @modes in the header, then the variables.
  3. It appears in the theme picker immediately; edits apply live while it's active.
  4. Optional: my-theme.bg.js draws on a full-size <canvas id="c"> behind the stage.

Or ask your agent: "make a Grimoire theme inspired by an old Mac terminal".
